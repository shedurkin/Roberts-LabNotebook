I originally ran MACAU with a very simple relatedness matrix created using the samples’ parent IDs, to essentially deliminate the half-sibs from everyone else. MACAU produced DML output, but the h2 values for almost all DMLs (h2 indicates heritability, or the portion of variance that can be attributed to relatedness) were stuck at the 0/1 bounds (see details here). This basically meant that the model couldn’t tell to what extent each site’s variation came from relatedness or from independent noise.

One of the data features that can cause this is collinearity between covariates – if relatedness overlaps with fixed effects (e.g., parental reatment condition), the fixed effect will obsorb the between-family differences, leaving little variance to be explained by relatedness. Generating a relatedness matrix manually from the parent IDs produced a relatedness matrix that was highly overlapping with parental treatment, since the offspring are stratified into either Control-only or Exposed-only parentage.

While this feature of the experimental design is unavoidable at this point, I can still try to generate a more accurate relatedness matrix that includes “background” relatedness values between all samples, not just the half-sibs. This can be done by doing SNP-calling on the WGBS data (using a tool that is bisulfite-aware, and won’t mistake C->T bisulfite conversions for genuine substitutions), then generating relatedness from that variant data. I’ve now done exactly that, using BS-Snper to call SNPs from the offspring WGBS data, then plink to generate a relatedness matrix from the output (see details here.

I will now rerun MACAU using this updated relatedness matrix to see if it improves ability to estimate heritability.

Results/Interpretation

Long story short, while MACAU still ran successfull and identified a similar number of parent-treatment-based DMLs, the h2 values were still largely bound to 0/1/NA, indicating the model is still unable to effectively parse variance attributable to relatedness. Moreover, the same proportion of DMLs produced non-0/1/NA h2 values – using the updated matrix, 44/624 (~7%) of DMLs had un-bound h2 values, while using the simplified matrix, 59/799 (~7%) did. This suggests to me that relatedness-treatment colinearity may not have been the (sole) underlying issue with effectively attributing site-level variance. It may also be related to the low sample size.

4 PQLseq2: binomial mixed model for parental-treatment effect

Fit, per CpG, a binomial mixed model:

meth_i / total_i ~ Binomial(total_i, p_i), logit(p_i) = intercept + treatment_i + stage_i + u_i, u ~ N(0, h2 * K)

  • Predictor tested (x) = parental treatment (Control = 0, Exposed = 1).
  • Covariate adjusted for (W) = stage (Zygote = 0, Larvae = 1). PQLseq2 fits its own intercept, so W holds covariates only.
  • Random-effect covariance (K) = the pedigree relatedness matrix.

Runs kept failing due to single sites throwing solve() errors and, while these only repesent fit failures for single CpG sites, the error kills the entire run. This should hopefully be addressed by the within-group filtering added above, but to make double sure I’m adding a wrapper tot he pqlseq2() function that essentially parses the full set of sites in chunks, and retries failed chunks in small batches. Ultimately, this should function to eaxclude failed sites from the run, rather than letting them corrupt/kill the whole job. Will also check, though, for how many sites ended up being dropped (high # could indicate lingering data preprocessing issues)

(utills::capture.output() added bc first successful run had thousands of lines of output messages about # of sites, chunks, etc.)

run_pqlseq2_safe <- function(Y, x, K, W, lib_size, chunk = 1000, ncores = 8, ...) {
  idx_chunks <- split(seq_len(nrow(Y)), ceiling(seq_len(nrow(Y)) / chunk))
  out <- vector("list", length(idx_chunks))
  for (i in seq_along(idx_chunks)) {
    rows <- idx_chunks[[i]]
    utils::capture.output(
    res  <- try(pqlseq2(Y = Y[rows, , drop = FALSE], x = x, K = K, W = W,
                        lib_size = lib_size[rows, , drop = FALSE],
                        ncores = ncores, ...), silent = TRUE)
    )
    if (inherits(res, "try-error")) {
      # if a site in this chunk threw a fatal solve() error, redo it site-by-site
      # so the singular one is dropped but its chunk-mates are kept
      res <- dplyr::bind_rows(lapply(rows, function(r) {
        utils::capture.output(
        s <- try(pqlseq2(Y = Y[r, , drop = FALSE], x = x, K = K, W = W,
                         lib_size = lib_size[r, , drop = FALSE],
                         ncores = 1, ...), silent = TRUE)
        )
        if (inherits(s, "try-error")) NULL else s
      }))
    }
    out[[i]] <- res
  }
  dplyr::bind_rows(out)
}

Breakdown of what each column represents:

  • n : The per-site sample size – for that site, how many individuals (out of 32) had coverage at this site and were used during model fitting
  • intercept : baseline methylation for the reference group (Control, Zygote) on the logit scale
  • se_intercept : SE of interecpt ^
  • beta : DML effect – change in log-odds methylation, adjusted for lifestage and relatedness. Sign indicates direction (hyper-or hypo-methylated)
  • se_beta : SE of beta ^
  • pvalue : Wald-test p-value (H_0 is beta=0, no treatment effect) – NOTE this is not corrected for multiple testing in default output, have to correct manually
  • h2 : heritability metric, fraction of latent variance assigned to relatedness – eaaentially, how much of methylation variance at the site is explained by pedigree. High h2 indicates signal at the DML is family-structured
  • sigma2: total variance component (kinship + residual)
  • converged : did the model fit converge?
  • elapsed_time : time required to fit the site

I’ve added:

  • padj : adjusted pvalue (BH, calculated from pvalue)
  • pos/chr parsed genomic coordinates

NOTE that beta is a logit-scale log-odds, not a % methylation difference, so magnitudes are not directly comparable to methylation difference values produced by DSS or methylKit. I can still, however, compare direction (+/- to indicate hyper-/hypomethylation) and rank.

save_bed <- function(df, path, score_col) {
  if (is.null(df) || nrow(df) == 0) {
    file.create(path)
    message("save_bed: no rows for ", basename(path), " — wrote empty file.")
    return(invisible(NULL))
  }
  if (all(c("chr","start","end") %in% names(df))) {
    start <- df$start; end <- df$end
  } else if (all(c("chr","pos") %in% names(df))) {
    start <- df$pos - 1L; end <- df$pos
  } else {
    stop("save_bed: df lacks chr/start/end or chr/pos for ", basename(path))
  }
  score <- if (score_col %in% names(df)) df[[score_col]] else NA_real_
  bed <- data.frame(chr = df$chr, start = start, end = end, score = score)
  write.table(bed, path, quote = FALSE, sep = "\t", row.names = FALSE, col.names = FALSE)
}
